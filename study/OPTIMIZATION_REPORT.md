## 8. 第二轮复查（2026-07-31 下午）

上一轮的结论在浏览器里复测时有两条没兑现，另有三处功能性缺陷在暗色背景下不容易看出来。本节记录复查发现和修法。

### 8.1 按需加载此前是失效的

`manualChunks` 只给 katex / markdown / reactflow 命名了分块，没给 React 自己命名。rollup 于是把 `react-dom`（128.6 kB）并进了 `vendor-graph`、把 `react` 并进了 `vendor-markdown`，入口块反过来静态依赖这两个重包：

```
index-*.js:  import{a,j,R}from"./vendor-markdown-*.js"
             import{r}from"./vendor-graph-*.js"
```

后果是构建产物 `index.html` 里对 katex / markdown / graph 三个包发 `modulepreload`，并把 katex、reactflow 的样式表提成渲染阻塞的 `<link>`。停在身份选择页什么都没做，也已经把整套 ReactFlow、d3-zoom、dagre 和 micromark 管线下完了。上一轮"分离成稳定依赖包，避免每次都下载重型模块"的说法与实际产物不符。

修法是在 `manualChunks` 里最先判定并单独切出 `vendor-react` 与 `vendor-router`。复测（干净会话首访首页）：

| 首屏 | 修前 | 修后 |
| --- | ---: | ---: |
| 入口静态依赖 JS（gzip） | 269.6 kB | 133.9 kB |
| 含 modulepreload 的首屏 JS（gzip） | 346.8 kB | 133.9 kB |
| 渲染阻塞样式表 | 3 个 / 23.6 kB gzip | 1 个 / 13.9 kB gzip |
| 首访实际拉取 JS 合计（gzip） | — | 204 kB |
| 首访是否加载 katex/markdown/graph/highlight | 是 | 否（0 个） |

katex、markdown、reactflow 现在只在进入资源中心、资源工坊、智能辅导、学习画像时才拉取。

### 8.2 粒子背景一直是坏的

`ParticleBg` 在 `useEffect` 里用 `canvas.offsetWidth` 做播撒范围，而挂载那一刻父容器往往还没完成布局，宽度是 0，于是 `Math.random() * 0` 把所有粒子生成在原点；`resize` 只监听 `window.resize`，不会补救。抓画布像素证实：

- 引导层画布 2560×1440，全部着色像素落在 `[0,0]–[68,64]`
- 首屏区块画布 2024×1406，全部着色像素落在 `x ≈ 0` 的 4 px 竖条里

也就是宣传里的"墨色星空"从来没有出现过，只是左上角一小坨噪点。改为归一化坐标 + `ResizeObserver` 后，两块画布的着色范围分别是 `[0,4]–[2472,1320]` 和 `[76,12]–[1992,1384]`，铺满整幅。

顺带修掉三处：`prefers-reduced-motion` 未被这条 rAF 循环遵守（上一轮声称已支持）；标签页切到后台仍在空转；连线判定用 `Math.hypot` 每帧开方上千次，改为比较距离平方。

写这段时踩过一次坑：最初把 `ResizeObserver` 挂在 canvas 自己身上，而回调里又会改 `canvas.width`，改固有尺寸触发新一轮回调，把画布压成 1×4534。改成观察父容器并让写入幂等才稳定。

### 8.3 思维导图的两个单位错误

`dagreLayout` 把 `ranksep` / `nodesep` 除以了 100，dagre 这两个参数的单位就是像素，所以层间距只剩 1.4 px、同层间距 0.9 px；`fitView({ padding: 40 })` 里 ReactFlow 的 padding 是比例不是像素。结果是 25 节点的导图挤成横向一条并且右侧被裁掉。

修法：去掉 `/100`，`padding` 改 0.15，节点宽度按标签长度算而不是一律 160 px，并在容器尺寸稳定后补一次 `fitView`（弹窗是动画进场的，`onInit` 那一刻宽度还不是最终值）。

改完整棵树能完整落在画布内，但缩放只有约 0.4，14 px 的节点字被压到 6 px 还是看不清。真正的瓶颈不在布局参数，而在容器：资源弹窗是 `max-w-3xl`（768 px），里面还套了一层 `max-w-2xl`，25 个节点被塞进约 620 px 宽的栏里，怎么排都得缩。两处一起改：

- 思维导图和动画这类图形资源，弹窗放宽到 `max-w-6xl`，内层不再用正文的窄栏（正文类资源保持窄栏，长段落宽度过大反而难读）。
- 导图默认只展开到主分支，二级以下收起。首屏是根 + 5 个主分支共 6 个节点，缩放到 1.0 以上，节点字是原始字号；分支上带 `+3` / `+4` 角标提示子节点数，点节点逐支展开，顶栏有「展开全部 / 收起子节点」。展开后自动重新适配。
- 缩略图从右下移到右上——右下默认位置正好盖住最后一个主分支。

节点计数从 `25 节点` 改成 `6/25 节点` 这种形式，展开状态一眼可见。

折叠态跟着组件实例走，换资源时由调用方传 `key` 重新挂载，不在 effect 里同步 state（这条被 `react-hooks/set-state-in-effect` 拦下过一次，改成 key 反而更干净）。

### 8.4 成品包双击打不开

构建默认 `base: '/'`，产出的 `index.html` 引用的是 `/assets/index-*.js` 这种绝对路径。
解压后双击打开时协议是 `file://`，浏览器会把 `/assets/` 解析到磁盘根目录，一个资源都拿不到，
页面全白。原始交付包也是这个问题。

两处一起改才够：

- `vite.config.ts` 设 `base: './'`，资源改为相对路径。
- 只改 base 还不行——`file://` 下 `location.pathname` 是磁盘路径，`BrowserRouter` 匹配不到
  任何路由，只会渲染 404。改成按协议选路由器：`file://` 用 `HashRouter`，其余仍用
  `BrowserRouter`，服务器部署下的深链写法完全不变。

验证：双击 `dist/index.html` 能正常进入身份选择页，点「决赛演示模式」跳到
`index.html#/showcase` 并正确渲染，控制台 0 条消息；`vite preview` 下 `location.hash` 为空，
`/library?resource=R-ai-intro-mindmap-1` 这类深链仍直接打开对应资源弹窗。

### 8.5 其余清理

- 删除三个无引用文件：`src/App 2.tsx`（旧版 App 副本，仍带着渲染期改状态的写法）、`src/hooks/useTheme.ts`（与 store 主题逻辑重复，且用的是另一个 localStorage key `theme`）、`src/components/StreamingText.tsx`。
- `build.sourcemap` 改为受 `BUILD_SOURCEMAP=true` 控制，默认关闭。`dist/` 从 9.7 MB 降到 2.4 MB——原先 6.1 MB 是没人消费的 `.map`。
- `index.html` 增加首帧前同步主题的内联脚本。此前 `<html class="dark">` 写死，浅色用户要等入口 JS 解析完才切过来，中间是一段深色闪烁。
- 144 份资源的正文、动画分镜、思维导图数据改为首次访问才构建并就地缓存。列表页和全局搜索只读 title / excerpt / metadata，不会触发构建。

关于最后一条要说实话：实测收益不大。模块求值从 10.1 ms 降到 7.2 ms（M4 Pro），推迟掉的构建总计约 2.9 ms（分镜 2.0 + 导图 0.23 + 正文 0.48）。真正的价值是首屏不再分配那 186 KB 字符串，而不是省下的毫秒。
