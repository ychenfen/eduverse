# 智学灵境 EduVerse · 系统开发说明书

> 高等教育个性化学习多智能体系统
> 版本：v2.0 · 文档日期：2026-07-18

## 一、需求分析

### 1.1 时代背景与痛点

在数字化与智能化深度融合的时代，高等教育面临**标准化教学与个性化需求**的根本矛盾：

| 痛点 | 表现 | 影响 |
|------|------|------|
| 资源繁杂无序 | 海量课程资料、文献、工具难以筛选 | 学生时间浪费在找资源而非学知识 |
| 集体讲授一刀切 | 课堂无法兼顾每位学生节奏与特点 | 知识掌握差距扩大 |
| 缺乏多模态生成 | 传统教辅系统仅提供文本 | 视觉型/实践型学习者吸收效率低 |
| 无智能体协同 | 单一 AI 助手能力有限 | 难以覆盖"拆解-撰写-出题-可视化-实操-校验"全链路 |
| 画像静态化 | 表单式画像一次填写终身不变 | 随学随新无法实现 |

### 1.2 目标用户画像

- **核心用户**：高校人工智能 / 计算机 / 电子信息相关专业本科生与研究生（18-25 岁）
- **典型场景**：课前预习、课后巩固、考研复习、项目实操、论文写作辅助
- **技术素养**：熟悉编程基础，对 AI 工具接受度高，期望流式、卡片化、可交互的现代体验

### 1.3 技术与需求结合点

| 学生需求 | 前沿 AI 技术 | 系统落地点 |
|---------|-------------|-----------|
| 摆脱繁琐表单 | 大模型自然语言理解 | 对话式画像抽取（灵境队长） |
| 多类型资源一站式生成 | 多智能体协同 + 多模态生成 | 6 智能体编队生成 6 类资源 |
| 知识结构可视化 | 知识图谱 + SVG 生成 | 解构者 + 视觉师协作 |
| 即时答疑解惑 | LLM 实时推理 | 智能辅导多模态回答 |
| 学习效果可量化 | 数据分析大模型 | 5 维评估 + 热力图 |
| 内容可信无幻觉 | RAG + 事实核查 | 校验官防幻觉机制 |

### 1.4 核心功能需求映射

| 赛题要求 | 系统实现 | 章节 |
|---------|---------|------|
| 对话式学习画像自主构建（≥6 维度） | 灵境队长 5 轮对话抽取 6 维特征，支持随学随新 | §3.1 |
| 多智能体协同资源生成（≥5 种类型） | 7 智能体编队生成 6 类资源（文档/导图/题库/阅读/动画/代码） | §3.2 |
| 个性化学习路径规划与资源推送 | 动态路径图谱 + 节点资源卡 + 动态调优 | §3.3 |
| 智能辅导（加分项） | 多模态答疑（文字+SVG图解+代码） | §3.4 |
| 学习效果评估（加分项） | 5 维雷达 + 热力图 + 调优方案 | §3.5 |
| 防幻觉与内容安全 | 校验官四重校验机制 | §3.6 |
| 流式输出 + 进度追踪 | async generator + 打字机 + 进度条 | §3.7 |

## 二、系统设计

### 2.1 总体架构

系统采用**四层架构**，前端驱动 + 智能体调度核心 + 服务层 + 数据层：

```
┌─────────────────────────────────────────────────────────┐
│  前端层 (React 18 + TypeScript + Vite + Tailwind)        │
│  ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┐    │
│  │工作台│画像  │工坊  │路径  │辅导  │评估  │资源  │    │
│  └──────┴──────┴──────┴──────┴──────┴──────┴──────┘    │
└───────────────────────┬─────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────┐
│  智能体调度核心 (src/agents/orchestrator.ts)              │
│  ┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐           │
│  │灵境 │解构 │编织 │出题 │视觉 │实操 │校验 │           │
│  │队长 │者   │者   │官   │师   │匠   │官   │           │
│  └─────┴─────┴─────┴─────┴─────┴─────┴─────┘           │
│  Orchestrator 编排器：任务分发 → 阶段调度 → 结果汇总     │
└───────────────────────┬─────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────┐
│  服务层 (src/services)                                   │
│  StreamingService │ SafetyService │ PathService         │
└───────────────────────┬─────────────────────────────────┘
                        │
┌───────────────────────▼─────────────────────────────────┐
│  数据层 (src/data)                                       │
│  课程知识库(24节点) │ Mock画像 │ 预生成资源池(144条)     │
└─────────────────────────────────────────────────────────┘
```

### 2.2 智能体设计

系统设计了 **7 个角色化智能体**，每个智能体有明确的职责边界与触发条件：

| 智能体 | 代号 | 职责 | 触发场景 | 核心能力 |
|--------|------|------|---------|---------|
| 灵境 | Captain | 对话引导、画像构建、任务分发 | 首次进入 / 画像更新 | 自然语言理解、特征抽取 |
| 解构者 | Deconstructor | 知识点拆解、思维导图骨架 | 文档/导图/路径生成 | 知识结构化、依赖分析 |
| 编织者 | Weaver | 内容主体撰写、拓展阅读 | 讲解文档/拓展阅读 | 学术叙事、类比例证 |
| 出题官 | QuizMaster | 题目生成、难度分级 | 题库资源 | 多题型生成、易错点靶向 |
| 视觉师 | Visualist | SVG 图解、动画分镜 | 教学动画/图解 | 多模态可视化设计 |
| 实操匠 | Coder | 代码案例、可运行片段 | 代码实操 | 代码生成、环境配置 |
| 校验官 | Validator | 事实核查、安全过滤 | 所有资源末段 | 防幻觉、引用补全 |

**协同流程**（以讲解文档为例）：
1. 灵境队长接收任务，调度编队
2. 解构者拆解知识结构 → 输出 5 主分支骨架
3. 编织者基于骨架撰写文档主体
4. 校验官对照知识库白名单核查、敏感词扫描、引用补全
5. 流式输出至学生，进度条实时更新

### 2.3 数据模型

#### 学生画像 6 维度

| 维度 | 取值 | 来源 | 示例 |
|------|------|------|------|
| 知识基础 | 0-100 | 对话自评 + 测验 | 高数 78 / 线代 65 |
| 认知风格 | 标签集合 | 对话偏好 | 视觉 + 实践 |
| 易错偏好 | 标签集合 | 历史错题 | 梯度爆炸 / QKV 顺序 |
| 学习节奏 | 枚举 | 时长统计 | 稳健（日均 1.8h） |
| 兴趣方向 | 标签集合 | 对话选择 | LLM 推理 / Multi-Agent |
| 目标导向 | 枚举 | 对话目标 | 考研 + 工程 |

#### 预置课程知识库

预置 1 门完整课程《人工智能导论》，6 章 / 24 知识点：

1. AI 绪论与发展史（4 节点）
2. 搜索与优化（4 节点）
3. 知识表示与推理（4 节点）
4. 机器学习基础（4 节点）
5. 深度学习（4 节点）
6. 大模型与多智能体（4 节点）

每知识点预置 6 类资源 × 24 节点 = **144 条预生成资源**作为系统输入。

### 2.4 防幻觉与安全过滤机制

校验官在每条资源生成末段执行四重校验：

1. **知识白名单校验**：对照本地 24 知识点 ID 白名单，非白名单内容打回
2. **语法校验**：代码块冒号匹配、公式语法、Markdown 结构
3. **敏感词过滤**：内置词表（暴力/色情/赌博/毒品/自残），可对接科大讯飞内容审核 API
4. **引用补全**：涉及论文的内容必须有显式引用标注，缺失则标注"待补充"

校验不通过则打回重生成（最多 2 次），仍不通过则降级为"草稿"标签展示。每条资源携带 `safetyCheck: { passed, flags, score }` 字段，安全分可视化展示。

## 三、功能实现

### 3.1 对话式学习画像构建

**实现文件**：`src/pages/Onboarding.tsx`、`src/pages/Profile.tsx`、`src/store/useAppStore.ts`

- 首次进入由灵境队长发起 5 轮自然语言对话
- 每轮回复实时抽取特征（专业/目标/基础/风格/易错点/节奏），右侧面板实时高亮显示已抽取特征
- 画像进度环可视化（0% → 100%）
- 完成后生成 v1 画像 + 首条学习路径
- 支持随学随新：在画像页点击"随学随新"按钮发起对话，更新维度并生成新版本
- 版本时间线支持历史对比（双雷达图并排）

### 3.2 多智能体协同资源生成

**实现文件**：`src/pages/Workshop.tsx`、`src/agents/orchestrator.ts`

- 调度台提供 6 类资源类型选择（卡片化）+ 24 知识点下拉 + 智能体编队预览
- 启动后右侧"智能体协作日志"实时滚动显示各智能体的"思考-生成-校验"过程
- 主区流式呈现 Markdown 内容（打字机效果 + 语法高亮）
- 进度追踪条基于 token 计数实时更新
- 完成后展示资源卡（含安全分徽章）
- 防白屏策略：3s 未首字输出显示骨架占位

### 3.3 个性化学习路径规划

**实现文件**：`src/pages/LearningPath.tsx`、`src/data/learner.ts`

- SVG 路径图谱：节点按章节分列，连线表示依赖关系
- 5 种节点状态色：未解锁/待学习/进行中/已完成/推荐加速
- 进行中与推荐节点带呼吸光晕动画
- 已完成节点连线带流光虚线动画
- 点击节点弹出右侧抽屉：知识点摘要、推荐理由、关联资源卡
- "动态调优"按钮：大模型基于学习行为生成跳级/补强/延后/巩固建议

### 3.4 智能辅导（加分项）

**实现文件**：`src/pages/Tutor.tsx`、`src/agents/orchestrator.ts`（tutorAnswer）

- 流式对话答疑，支持自然语言提问
- 4 个建议问题快速入口
- 多模态回答：文字 + Markdown 公式 + SVG 图解卡片 + 代码片段
- 右侧上下文记忆面板：显示当前画像版本、易错点靶向、认知风格
- 历史提问快速重问
- 内置 3 个领域知识库（梯度问题/注意力/A*），可平滑扩展

### 3.5 学习效果评估（加分项）

**实现文件**：`src/pages/Assessment.tsx`

- 4 个关键指标卡：平均掌握度/累计学习/题库正确率/题库完成
- 5 维效果雷达图（掌握度/熟练度/迁移力/坚持度/创新力）含班级基准对比
- 24 知识点掌握热力图（5 级色阶）
- 薄弱知识点 TOP 3 自动识别
- 详细学习记录表（掌握度进度条、时长、题库、最近访问）
- "生成调优方案"按钮：大模型输出资源推送策略调整 + 学习计划动态调整

### 3.6 防幻觉与内容安全

**实现文件**：`src/services/safety.ts`

详见 §2.4。每条生成资源携带安全分（0-100），在资源卡与生成结果区可视化展示。

### 3.7 流式输出与防白屏

**实现文件**：`src/services/streaming.ts`

- 基于 `async function*` 生成器逐 token 产出
- 标点处自然停顿（4 倍速），模拟真实打字节奏
- 前端 `for await` 消费 + 30ms 节流渲染
- 进度条基于 token 计数 / 总预估
- 智能体协作日志实时滚动，让用户感知后台工作
- 多模态卡片在文本流中通过 `[SVG:id]` 占位标记，渲染时替换为对应组件

## 五、前沿 AI 技术融合应用

### 5.1 大模型技术体系应用

| 技术 | 应用点 | 实现方式 |
|------|--------|---------|
| 通用大模型 | 对话理解、内容生成 | AgentService 预留 Provider 接口，可对接讯飞星火/OpenAI/Claude |
| 多模态生成 | SVG 图解、动画分镜 | 视觉师智能体生成 SVG + 分镜脚本 |
| 代码辅助 | 代码实操案例 | 实操匠智能体生成可运行 Python + 单元测试 |
| 实时推理 | 智能辅导答疑 | 流式输出 + 上下文记忆 |

### 5.2 多智能体协同框架

系统采用**自研轻量编排器**（`src/agents/orchestrator.ts`），未引入第三方 Agent 框架以保证可独立运行：

- **角色分工**：7 个智能体各司其职，职责边界清晰
- **阶段调度**：每类资源有固定的智能体编队顺序（如文档 = 解构者→编织者→校验官）
- **消息传递**：通过 `onLog` 回调实时传递智能体状态
- **结果汇总**：编排器汇总各智能体输出，交由校验官最终校验
- **可扩展性**：预留 Provider 接口，可平滑切换至 LangGraph、AutoGen、讯飞 Agent 框架

### 5.3 创新实践

1. **对话式画像替代表单**：5 轮自然语言对话抽取 6 维特征，零表单填写
2. **随学随新画像版本化**：画像支持版本管理与历史对比，真正动态
3. **多模态卡片流式占位**：`[SVG:id]` 标记在流中占位，渲染时替换为卡片
4. **校验官防幻觉四重校验**：白名单 + 语法 + 敏感词 + 引用，安全分可视化
5. **智能体编队可视化**：首页环形排列 + 呼吸光，让"多智能体"可见可感
6. **路径动态调优**：基于学习行为生成跳级/补强建议，路径非静态

### 6.2 运行环境

- Node.js ≥ 18
- npm ≥ 9（或 pnpm）
- 现代浏览器（Chrome/Edge/Firefox 最新版）

### 6.3 启动命令

```bash
npm install      # 安装依赖
npm run dev      # 启动开发服务器（http://localhost:5173）
npm run build    # 生产构建
npm run check    # TypeScript 类型检查
```

### 6.4 大模型接入说明

Demo 阶段使用本地"剧本式"流式回放（保证演示稳定且可独立运行）。生产部署时：

1. 在 `src/agents/orchestrator.ts` 中实现 `Provider` 接口
2. 对接科大讯飞星火大模型 API（推荐，符合赛题"使用科大讯飞相关工具"要求）
3. 将 `orchestrate()` 中的预生成内容替换为真实 LLM 调用
4. 将 `tutorAnswer()` 替换为真实对话 API
5. 安全过滤可升级为讯飞内容审核 API

## 八、用户体验提升策略

1. **零表单对话引导**：5 轮自然语言对话替代繁琐注册表单
2. **流式呈现 + 进度追踪**：避免长时间白屏，用户感知后台工作
3. **多模态卡片化**：6 类资源各自定制卡片视觉，信息密度高
4. **双主题切换**：墨夜（默认）与宣纸（浅色），适配不同环境
5. **智能体编队可视化**：环形排列 + 呼吸光，让"多智能体"可见可感
6. **雷达图绘制动画**：easeOutCubic 缓动，入场更有质感
7. **粒子背景**：Canvas 实现的星点连线，营造学术氛围
8. **快捷入口**：工作台 4 个一键入口，降低操作成本
9. **路径节点呼吸光**：进行中/推荐节点带光晕，引导注意力
10. **热力图悬浮提示**：知识点掌握度一目了然
